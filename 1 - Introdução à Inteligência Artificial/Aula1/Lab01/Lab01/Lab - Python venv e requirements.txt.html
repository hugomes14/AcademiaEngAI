Lab - Python venv e requirements.txt

Nota inicial

Nestes laboratórios vamos usar o comando python.

Em alguns sistemas, especialmente macOS ou Linux, o comando pode ser python3.

Se python não funcionar, usa:

python3

Exemplo:

python3 -m venv .venv

em vez de:

python -m venv .venv

Lab 1 — Um projecto com um único ambiente virtual

Objectivo

Neste laboratório vais criar um projecto Python com um único ambiente virtual.

A ideia é comparar dois momentos:

antes do .venv  -> Python global
depois do .venv -> Python do projecto

No fim, deves perceber que:

  • antes de activar o .venv, o terminal usa o Python global;
  • depois de activar o .venv, o terminal usa o Python do projecto;
  • o requirements.txt pertence ao projecto;
  • o pip instala bibliotecas no ambiente Python que estiver activo.

1. Criar a pasta do projecto

Cria uma pasta chamada:

lab-venv-simples

Entra nessa pasta pelo terminal.

A estrutura final será:

lab-venv-simples/
│
├── app.py
├── requirements.txt
└── .venv/

Nesta fase, a pasta .venv ainda não existe.

2. Confirmar o Python usado antes do ambiente virtual

Antes de criares qualquer ambiente virtual, executa:

python -c "import sys; print(sys.executable)"

Se o teu sistema usar python3, executa:

python3 -c "import sys; print(sys.executable)"

Deves ver o caminho do Python instalado no sistema.

Exemplo no Windows:

C:\Users\Utilizador\AppData\Local\Programs\Python\Python312\python.exe

Exemplo em macOS/Linux:

/usr/bin/python3

Nesta fase, ainda não deve aparecer .venv no caminho.

Isto significa que estás a usar o Python global do sistema.

3. Criar o ficheiro requirements.txt

Cria o ficheiro:

requirements.txt

Com este conteúdo:

requests

Este ficheiro é a lista de bibliotecas necessárias para este projecto.

Ele não instala nada sozinho.

4. Criar o ficheiro app.py

Cria o ficheiro:

app.py

Com este conteúdo:

import sys
import requests

print("Aplicação executada com sucesso.")
print()
print("Python usado:")
print(sys.executable)
print()
print("Versão da biblioteca requests:")
print(requests.__version__)

5. Criar o ambiente virtual

Dentro da pasta do projecto, executa:

python -m venv .venv

Se o teu sistema usar python3, executa:

python3 -m venv .venv

Depois disto, a pasta .venv passa a existir dentro do projecto.

lab-venv-simples/
│
├── app.py
├── requirements.txt
└── .venv/

A pasta .venv é o ambiente Python privado deste projecto.

6. Activar o ambiente virtual

Usa o comando adequado ao teu terminal.

Windows — Command Prompt

.venv\Scripts\activate

Windows — PowerShell

.venv\Scripts\Activate.ps1

macOS / Linux — Bash ou Zsh

source .venv/bin/activate

Depois da activação, o terminal deve mostrar algo parecido com:

(.venv)

Isto indica que o ambiente virtual está activo.

7. Confirmar novamente qual é o Python usado

Agora executa outra vez:

python -c "import sys; print(sys.executable)"

O resultado deve mostrar um caminho com .venv.

Exemplo no Windows:

...\lab-venv-simples\.venv\Scripts\python.exe

Exemplo em macOS/Linux:

/.../lab-venv-simples/.venv/bin/python

A parte importante é esta:

.venv

Agora já não estás a usar directamente o Python global.

Estás a usar o Python do ambiente virtual deste projecto.

8. Instalar as dependências do projecto

Com o ambiente virtual activo, executa:

python -m pip install -r requirements.txt

Este comando significa:

usa o Python activo
usa o pip desse Python
lê o requirements.txt
instala as bibliotecas nesse ambiente

Como o .venv está activo, a biblioteca requests fica instalada dentro do .venv.

9. Confirmar onde a biblioteca ficou instalada

Executa:

python -m pip show requests

Procura a linha:

Location:

Deves ver um caminho que contém .venv.

Exemplo:

Location: .../lab-venv-simples/.venv/.../site-packages

Isto confirma que a biblioteca foi instalada dentro do ambiente virtual do projecto.

10. Executar a aplicação

Executa:

python app.py

Resultado esperado:

Aplicação executada com sucesso.

Python usado:
.../.venv/...

Versão da biblioteca requests:
2.x.x

A aplicação funcionou porque o ambiente virtual tem a biblioteca requests instalada.

11. Desactivar o ambiente virtual

Executa:

deactivate

O indicador (.venv) desaparece.

Isto não apaga o .venv.

Apenas deixa de usar esse ambiente no terminal actual.

12. Confirmar o Python usado depois de desactivar

Executa novamente:

python -c "import sys; print(sys.executable)"

Agora o caminho já não deve apontar para .venv.

Ou seja:

com .venv activo    -> Python do projecto
sem .venv activo    -> Python global

13. Experiência final

Apaga a pasta:

.venv/

Depois volta a fazer:

python -m venv .venv

Activa novamente o ambiente virtual e executa:

python -m pip install -r requirements.txt

Isto mostra que:

.venv             -> pode ser recriado
requirements.txt -> deve ser guardado

Conclusão do Lab 1

A relação principal é esta:

requirements.txt

é a lista de bibliotecas do projecto.

.venv

é o ambiente onde essas bibliotecas ficam instaladas.

python -m pip install -r requirements.txt

instala as bibliotecas no Python que estiver activo.

Se o .venv estiver activo, as bibliotecas ficam no .venv.

A comparação essencial é:

antes de activar .venv:
Python global

depois de activar .venv:
Python do projecto

Lab 2 — Um projecto com dois ambientes virtuais

Objectivo

Neste laboratório vais criar dois ambientes virtuais no mesmo projecto.

A ideia é perceber que:

  • um projecto pode ter mais do que um ambiente virtual;
  • cada ambiente virtual tem as suas próprias bibliotecas;
  • só um ambiente virtual fica activo de cada vez;
  • o pip instala sempre no ambiente activo.

1. Criar a pasta do projecto

Cria uma pasta chamada:

lab-venv-duplo

Entra nessa pasta pelo terminal.

A estrutura final será:

lab-venv-duplo/
│
├── app.py
├── requirements-web.txt
├── requirements-tools.txt
│
├── .venv-web/
└── .venv-tools/

Neste laboratório vamos ter dois ambientes:

.venv-web    -> ambiente com requests
.venv-tools  -> ambiente com rich

2. Confirmar o Python usado antes dos ambientes virtuais

Antes de criares os ambientes virtuais, executa:

python -c "import sys; print(sys.executable)"

Se o teu sistema usar python3, executa:

python3 -c "import sys; print(sys.executable)"

Nesta fase, o caminho não deve ter .venv-web nem .venv-tools.

Ainda estás a usar o Python global.

3. Criar o ficheiro requirements-web.txt

Cria o ficheiro:

requirements-web.txt

Com este conteúdo:

requests

Este ficheiro será usado apenas para o ambiente .venv-web.

4. Criar o ficheiro requirements-tools.txt

Cria o ficheiro:

requirements-tools.txt

Com este conteúdo:

rich

Este ficheiro será usado apenas para o ambiente .venv-tools.

5. Criar o ficheiro app.py

Cria o ficheiro:

app.py

Com este conteúdo:

import sys
import importlib.util

def existe_biblioteca(nome):
    return importlib.util.find_spec(nome) is not None

print("Aplicação executada.")
print()
print("Python usado:")
print(sys.executable)
print()

print("Bibliotecas disponíveis neste ambiente:")
print("requests:", "SIM" if existe_biblioteca("requests") else "NÃO")
print("rich:", "SIM" if existe_biblioteca("rich") else "NÃO")

Este programa mostra:

  • qual é o Python activo;
  • se requests existe nesse ambiente;
  • se rich existe nesse ambiente.

Parte A — Criar e usar o ambiente .venv-web

6. Criar o ambiente .venv-web

Executa:

python -m venv .venv-web

Se o teu sistema usar python3, executa:

python3 -m venv .venv-web

7. Activar o ambiente .venv-web

Usa o comando adequado ao teu terminal.

Windows — Command Prompt

.venv-web\Scripts\activate

Windows — PowerShell

.venv-web\Scripts\Activate.ps1

macOS / Linux — Bash ou Zsh

source .venv-web/bin/activate

O terminal deve mostrar algo parecido com:

(.venv-web)

8. Confirmar que o Python activo é o da .venv-web

Executa:

python -c "import sys; print(sys.executable)"

O caminho deve conter:

.venv-web

Isto confirma que estás a usar o primeiro ambiente virtual.

9. Instalar as dependências do ambiente .venv-web

Com o .venv-web activo, executa:

python -m pip install -r requirements-web.txt

Este comando instala requests dentro do ambiente .venv-web.

10. Executar a aplicação no ambiente .venv-web

Executa:

python app.py

Resultado esperado:

Aplicação executada.

Python usado:
.../.venv-web/...

Bibliotecas disponíveis neste ambiente:
requests: SIM
rich: NÃO

Isto mostra que o ambiente .venv-web tem requests, mas não tem rich.

11. Desactivar o ambiente .venv-web

Executa:

deactivate

O indicador (.venv-web) desaparece.

Parte B — Criar e usar o ambiente .venv-tools

12. Criar o ambiente .venv-tools

Executa:

python -m venv .venv-tools

Se o teu sistema usar python3, executa:

python3 -m venv .venv-tools

13. Activar o ambiente .venv-tools

Usa o comando adequado ao teu terminal.

Windows — Command Prompt

.venv-tools\Scripts\activate

Windows — PowerShell

.venv-tools\Scripts\Activate.ps1

macOS / Linux — Bash ou Zsh

source .venv-tools/bin/activate

O terminal deve mostrar algo parecido com:

(.venv-tools)

14. Confirmar que o Python activo é o da .venv-tools

Executa:

python -c "import sys; print(sys.executable)"

O caminho deve conter:

.venv-tools

Isto confirma que estás a usar o segundo ambiente virtual.

15. Instalar as dependências do ambiente .venv-tools

Com o .venv-tools activo, executa:

python -m pip install -r requirements-tools.txt

Este comando instala rich dentro do ambiente .venv-tools.

16. Executar a aplicação no ambiente .venv-tools

Executa:

python app.py

Resultado esperado:

Aplicação executada.

Python usado:
.../.venv-tools/...

Bibliotecas disponíveis neste ambiente:
requests: NÃO
rich: SIM

Isto mostra que o ambiente .venv-tools tem rich, mas não tem requests.

17. Alternar entre ambientes

Para mudar de ambiente, primeiro desactiva o ambiente actual:

deactivate

Depois activa o outro.

Activar .venv-web

Windows Command Prompt:

.venv-web\Scripts\activate

Windows PowerShell:

.venv-web\Scripts\Activate.ps1

macOS/Linux:

source .venv-web/bin/activate

Activar .venv-tools

Windows Command Prompt:

.venv-tools\Scripts\activate

Windows PowerShell:

.venv-tools\Scripts\Activate.ps1

macOS/Linux:

source .venv-tools/bin/activate

18. Ideia principal

No mesmo projecto temos:

requirements-web.txt

Lista as bibliotecas para o ambiente .venv-web.

requirements-tools.txt

Lista as bibliotecas para o ambiente .venv-tools.

.venv-web

Guarda as bibliotecas instaladas para o ambiente web.

.venv-tools

Guarda as bibliotecas instaladas para o ambiente de ferramentas.

19. Conclusão do Lab 2

Um projecto pode ter vários ambientes virtuais.

Mas o terminal só usa um de cada vez.

Quando executas:

python -m pip install -r requirements-web.txt

o pip instala no ambiente que estiver activo nesse momento.

Quando executas:

python app.py

a aplicação corre com o Python do ambiente activo.

Por isso, antes de instalar ou executar código, confirma sempre qual é o Python activo:

python -c "import sys; print(sys.executable)"

Se o caminho tiver .venv-web, estás no ambiente web.

Se o caminho tiver .venv-tools, estás no ambiente tools.

Resumo final

Um ambiente virtual

projecto/
│
├── app.py
├── requirements.txt
└── .venv/

Usa-se quando o projecto só precisa de um conjunto de dependências.

Dois ambientes virtuais

projecto/
│
├── app.py
├── requirements-web.txt
├── requirements-tools.txt
│
├── .venv-web/
└── .venv-tools/

Usa-se quando queres testar dependências diferentes ou separar contextos diferentes.

Regra principal

O pip instala no Python que estiver activo.

Por isso, antes de instalar dependências, confirma sempre:

python -c "import sys; print(sys.executable)"
