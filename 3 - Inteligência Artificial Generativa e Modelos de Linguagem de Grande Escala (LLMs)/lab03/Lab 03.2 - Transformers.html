Ex 01: Preparar Ambiente e Dados

  1. Importar Bibliotecas: torch, transformers, json, matplotlib, etc.
  2. Configurar Dispositivo e Sementes: Definir o device (GPU/CPU) e fixar as sementes aleatórias para reprodutibilidade.
  3. Carregar SQuAD: Ler o ficheiro train-v1.1.json, percorrer a estrutura aninhada e extrair três listas: Perguntas, Respostas e Contextos.

Ex 02: Tokenização e Codificação de Sequências

  1. Inicializar Tokenizer: Carregar o AutoTokenizer do T5-Small.
  2. Definir Constantes: Definir IDs especiais (PAD, EOS, BOS) e tamanhos máximos (MAX_SRC_LEN, MAX_TGT_LEN).
  3. Função encode_src: Criar uma função que recebe Pergunta e Contexto, tokeniza ambos e concatena-os com separadores ([SEP]). Deve incluir lógica de “orçamento” para truncar o contexto se a soma exceder o limite, preservando a pergunta.
  4. Função encode_tgt: Criar uma função para a resposta alvo, adicionando o token [BOS] no início e [EOS] no fim.

Ex 03: Criar Dataset e Dataloaders

  1. Classe QADataset: Implementar um Dataset PyTorch que aplica as funções de codificação criadas no Ex 02.
  2. Função pad_collate: Criar uma função para fazer batching dinâmico, aplicando padding nas sequências de entrada e saída até ao comprimento máximo do lote atual.
  3. DataLoaders: Dividir os dados em treino (90%) e validação (10%) e criar os respetivos DataLoader.

Ex 04: Implementar Mecanismos de Atenção

  1. MultiHeadAttention: Implementar a atenção padrão (para o Encoder e Cross-Attention). Deve projetar Q, K, V, calcular scores (scaled dot-product), aplicar máscaras de padding e retornar o contexto.
  2. MaskedMultiHeadAttention: Implementar a atenção com máscara causal (triângulo inferior) para o Decoder, garantindo que o modelo não consegue “ver o futuro” (tokens seguintes) durante o treino.

Ex 05: Implementar Camadas e Modelo Completo

  1. TransformerEncoderLayer: Criar a camada do Encoder contendo: Self-Attention, FeedForward, Normalização (LayerNorm) e conexões residuais.
  2. TransformerDecoderLayer: Criar a camada do Decoder contendo: Masked Self-Attention, Cross-Attention (ligando ao output do Encoder), FeedForward, Normalização e resíduos.
  3. Classe QATransformer: Juntar tudo numa classe nn.Module que inclua:
  • Embeddings de palavras e posicionais.
  • Stack de N camadas de Encoder e N camadas de Decoder.
  • Camada linear final (lm_head) para projetar para o vocabulário.
  • (Opcional) Weight Tying entre embeddings e a camada de saída.

Ex 06: Instanciar Modelo e Otimizador

  1. Inicializar Modelo: Instanciar o QATransformer com dimensões adequadas (ex: d_model=256, nhead=4) e mover para o dispositivo.
  2. Otimizador: Configurar o AdamW com uma learning rate inicial (ex: 3e-4).
  3. Scheduler: Implementar um LR Scheduler com aquecimento (warmup) e decaimento cosseno.

Ex 07: Definir Funções de Passo e Avaliação

  1. _step_batch: Criar uma função auxiliar que executa um passo forward:
  • Gera as máscaras de padding.
  • Prepara o input do decoder (tgt_in) e o alvo (tgt_out) deslocando os tokens (Teacher Forcing).
  • Calcula a CrossEntropyLoss ignorando o índice de padding.
  1. evaluate: Função para calcular a perda média no conjunto de validação sem atualizar gradientes.

Ex 08: Implementar Loop de Treino

  1. Ciclo de Épocas: Implementar o loop principal de treino.
  2. Passo de Treino: Zerar gradientes, calcular loss, fazer backpropagation, aplicar gradient clipping (norma 1.0) e atualizar pesos.
  3. Logging e Checkpoint: Registar a perda e guardar os pesos do modelo (state_dict) no final de cada época.

Ex 09: Inferência com Greedy Decoding

  1. Algoritmo Guloso: Implementar a função greedy_answer que:
  • Codifica a pergunta e contexto.
  • Alimenta o Decoder passo a passo, começando com [BOS].
  • Em cada passo, escolhe o token com maior probabilidade (argmax) e adiciona-o à sequência até encontrar [EOS].
  1. Teste: Executar a função em alguns exemplos do conjunto de validação.

Ex 10: Visualizar Curva de Aprendizagem

  1. Plot: Utilizar o matplotlib para desenhar o gráfico da perda de treino ao longo dos passos.
  2. Média Móvel: Aplicar uma função de suavização para facilitar a leitura da tendência do erro.

Ex 11: Script de Inferência Standalone (Chatbot)

Neste exercício, vamos criar um script separado do treino. O objetivo é simular um ambiente de produção onde o modelo já está treinado e queremos apenas utilizá-lo para responder a novas perguntas.

Nota Importante: Como o PyTorch guarda apenas os pesos (números) e não o código do modelo, é obrigatório redefinir as classes da arquitetura neste novo script para que os pesos possam ser carregados na estrutura correta.

  1. Redefinir a Arquitetura:
  • Copiar as classes MultiHeadAttention, TransformerEncoderLayer, TransformerDecoderLayer e QATransformer tal como foram definidas no treino.
  • Garantir que os hiperparâmetros (ex: d_model=256, nhead=4) coincidem exatamente com os usados no treino.
  1. Carregar os Pesos (load_state_dict):

  • Instanciar o modelo “vazio” e movê-lo para o dispositivo.

  • Utilizar torch.load para ler o ficheiro .pt (ex: modelo_squad_epoch_4.pt).

  • Dica: Usar o argumento map_location=device para garantir compatibilidade caso o modelo tenha sido treinado em GPU e esteja a ser carregado em CPU (ou vice-versa).

  • Carregar os pesos no modelo com model.load_state_dict.

  • Crucial: Executar model.eval() para desativar camadas de Dropout e fixar a LayerNorm.

  1. Funções de Pré-processamento de Inferência:
  • Implementar encode_src_inference: Ao contrário do treino (que processa batches), esta função deve receber uma única string de pergunta e contexto, tokenizá-las e retornar um tensor com dimensão de batch 1 ([1, seq_len]).
  1. Geração de Texto (Loop de Predição):
  • Implementar a função get_answer que realiza a geração passo-a-passo:
  1. Alimenta o Encoder com a pergunta/contexto.
  2. Inicializa o Decoder apenas com o token [BOS].
  3. Num ciclo for (até max_new_tokens):
  • Obtém a previsão do próximo token (argmax dos logits).
  • Se for [EOS], termina a geração.
  • Caso contrário, concatena o novo token à entrada do Decoder e repete.
  1. Interface de Chat Interativa:
  • Criar um ciclo while infinito que:
  • Pede ao utilizador um Contexto (parágrafo de texto).
  • Entra num sub-ciclo para pedir várias Perguntas sobre esse contexto.
  • Chama a função de geração e imprime a resposta do modelo.
  • Permite comandos de saída (ex: “sair”, “mudar”) para encerrar o programa ou trocar de contexto.
