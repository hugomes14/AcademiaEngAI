Ex 0: Servir o modelo local no LM Studio

Pré-requisitos do lab: LM Studio com o modelo gemma-4-e2b-it descarregado, Docker Desktop (ou Docker + Compose), Git e uma API key da OpenAI (https://platform.openai.com/api-keys) para o Ex 4.

  1. Abra o LM Studio e carregue o modelo gemma-4-e2b-it. Por omissão, a API só expõe os modelos que estão carregados em memória.
  2. Vá ao separador Developer e ative o servidor local (Start Server). A porta por omissão é 1234.
  3. (Opcional) Ative o Just in Time Model Loading para os modelos instalados aparecerem na API sem estarem carregados.

Verificação: abra no browser http://localhost:1234/v1/models. Deve ver algo como:

{ "data": [ { "id": "gemma-4-e2b-it", ... } ] }

Se "data" vier vazio, o modelo não está carregado.

Ex 1: Instalar o LibreChat

No terminal (Windows primeiro; alternativa Linux/macOS em seguida):

git clone https://github.com/danny-avila/LibreChat.git
cd LibreChat
copy .env.example .env
# Linux/macOS
cp .env.example .env

Ainda não inicie nada. Primeiro, vamos configurar as ligações.

Ex 2: Ligar o LibreChat ao LM Studio

2.1 Criar o ficheiro librechat.yaml

Na raiz do projeto LibreChat, crie o ficheiro librechat.yaml:

version: 1.3.5
cache: true

endpoints:
  custom:
    - name: "LM Studio"
      apiKey: "lm-studio"
      baseURL: "http://host.docker.internal:1234/v1"
      models:
        default: ["default"]
        fetch: true
      titleConvo: true
      titleModel: "current_model"
      modelDisplayLabel: "LM Studio"
  • baseURL: dentro do Docker, localhost aponta para o próprio contentor, por isso usamos host.docker.internal, que aponta para a sua máquina.
  • fetch: true: o LibreChat vai buscar ao LM Studio a lista de modelos carregados (por isso o modelo tem de estar carregado no Ex 0).
  • titleModel: "current_model": o título da conversa é gerado pelo mesmo modelo que está a usar.

2.2 Montar o ficheiro no contentor

Crie o ficheiro docker-compose.override.yml na raiz do projeto:

services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml

Sem este ficheiro, o contentor não vê o librechat.yaml e ignora a configuração.

2.3 Arrancar

docker compose up -d

Abra http://localhost:3080, crie uma conta (fica apenas na sua instalação) e entre.

Verificação: no seletor de endpoints, no topo, deve aparecer LM Studio com o modelo gemma-4-e2b-it.

2.4 Se o modelo não aparecer

curl http://host.docker.internal:1234/v1/models

Deve devolver a mesma lista do Ex 0. Se der erro, o contentor não chega à sua máquina. Em Linux, acrescente ao docker-compose.override.yml, dentro de api:

    extra_hosts:
      - "host.docker.internal:host-gateway"

Se o comando devolver que o curl não existe na imagem, use o teste da secção Resolução de problemas, que corre o curl num contentor temporário.

Ex 3: Primeira conversa com o modelo local

  1. No seletor do topo, escolha LM Studio e o modelo gemma-4-e2b-it.
  2. Escreva: Explica em 3 frases o que é um modelo de linguagem.
  3. Observe a resposta a chegar em streaming e o título que a conversa ganha automaticamente.

Verificação: o LM Studio mostra os pedidos em Developer → Logs. Confirme que o pedido chegou lá, o que prova que a resposta é gerada no seu computador.

Ex 4: Ligar à OpenAI

  1. Abra o .env e procure a linha OPENAI_API_KEY.

  2. Defina a sua chave:

    OPENAI_API_KEY=sk-...a-tua-chave...
# Opcional: limitar os modelos apresentados
OPENAI_MODELS=gpt-4o,gpt-4o-mini

  3. Reinicie:

    docker compose down && docker compose up -d

  4. Faça hard refresh no browser (Ctrl + Shift + R).

Verificação: no seletor de endpoints aparece agora OpenAI.

Segurança: nunca partilhe o .env nem o submeta para o Git. A chave está ligada à sua faturação.

Ex 5: Utilização básica do LibreChat

5.1 Nova conversa e histórico

  • Nova conversa (canto superior esquerdo) inicia uma conversa limpa.
  • A barra lateral guarda o histórico. Pode pesquisar, renomear e apagar conversas.

5.2 Trocar de modelo

Use o seletor do topo para alternar entre LM Studio e OpenAI.

Tarefa A: pergunte aos dois modelos “Resume o que é o RGPD em 5 linhas.” Compare qualidade, tempo de resposta e estilo.

5.3 Parâmetros do modelo

Abra o painel de parâmetros (ícone junto ao seletor de modelo) e altere a Temperature (0.1 = mais previsível, 1.0 = mais criativo).

Tarefa B: peça “Escreva um slogan para uma padaria” com temperatura 0.1 e depois 1.0. O que muda?

5.4 Presets

Um preset guarda modelo, parâmetros e instruções. Crie o preset Tradutor PT-EN com a instrução: “Traduza sempre o texto do utilizador de português para inglês, sem comentários.”

Tarefa C: use o preset com uma frase sua e verifique se obedece.

5.5 Anexar ficheiros

Use o ícone de clipe para anexar uma imagem ou PDF. Modelos locais pequenos podem não suportar imagens: teste também com a OpenAI (gpt-4o) e compare.

5.6 Editar, regenerar e exportar

  • Editar uma mensagem sua e reenviar.
  • Regenerar uma resposta para ver alternativas.
  • No menu da conversa, Exportar guarda em Markdown, JSON ou texto.

Ex 6: Pesquisa web com SearXNG

A pesquisa web no LibreChat tem três componentes: um fornecedor de pesquisa (aqui o SearXNG), um scraper que lê o conteúdo das páginas (aqui o Keenable, que não precisa de chave) e um reranker opcional (vamos desativá-lo).

O SearXNG é um metapesquisador que corre na sua máquina e, por omissão, consulta google,bing,duckduckgo. Quem pesquisa é o LibreChat: chama o SearXNG, recebe os resultados e entrega-os ao modelo como texto. O modelo do LM Studio não precisa de acesso à internet.

6.1 Acrescentar o SearXNG ao Docker

Substitua o conteúdo do docker-compose.override.yml por:

services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
    depends_on:
      - searxng

  searxng:
    image: searxng/searxng:latest
    container_name: searxng
    ports:
      - "8080:8080"
    volumes:
      - ./searxng:/etc/searxng
    environment:
      - SEARXNG_BASE_URL=http://localhost:8080/
    restart: unless-stopped

O volume do SearXNG tem de ser ./searxng:/etc/searxng, com o caminho de destino absoluto (a começar por /) dentro do contentor. Um volume escrito só como searxng dá o erro mount path must be absolute.

6.2 Configurar o SearXNG para devolver JSON

O LibreChat pede os resultados em JSON, e o SearXNG não o permite por omissão.

  1. Crie a pasta searxng na raiz do projeto.

  2. Inicie uma vez para o SearXNG gerar o ficheiro de definições:

    docker compose up -d searxng

  3. Abra searxng/settings.yml e deixe-o assim. Atenção: search: fica ao nível da raiz, sem indentação. Se ficar dentro de server:, o SearXNG ignora o formats e continua a devolver só HTML.

    use_default_settings: true

server:
  secret_key: "COLOQUE_AQUI_UMA_CHAVE_ALEATORIA"
  image_proxy: true
  limiter: false

search:
  formats:
    - html
    - json
    • Mantenha a secret_key que o SearXNG gerou no seu ficheiro. Não a partilhe.
    • limiter: false desativa o filtro anti-bots, que não faz falta numa instância privada e pode recusar pedidos que chegam sem cabeçalhos de proxy.

  4. Reinicie o SearXNG:

    docker compose restart searxng

Verificação: abra http://localhost:8080 e faça uma pesquisa. Depois teste a API. No PowerShell use curl.exe, porque curl é um alias de outro comando:

curl.exe -s "http://localhost:8080/search?q=librechat&format=json" | more

Deve devolver JSON com results. Se devolver um erro 403, veja a secção Resolução de problemas.

6.3 Configurar o LibreChat

Acrescente ao .env:

SEARXNG_INSTANCE_URL=http://searxng:8080

E acrescente ao fim do librechat.yaml:

webSearch:
  searchProvider: "searxng"
  searxngInstanceUrl: "${SEARXNG_INSTANCE_URL}"
  searxngSearchOptions:
    engines: "google,bing,duckduckgo"
    language: "pt"
    timeout: 10000
  scraperProvider: "keenable"
  rerankerType: "none"
  safeSearch: 1
  # Obrigatório: o SearXNG está numa rede privada e o LibreChat bloqueia esses destinos por omissão
  allowedAddresses:
    - "searxng:8080"
  • No librechat.yaml nunca se colocam URLs ou chaves reais, só nomes de variáveis ${...}.
  • searxng:8080 é o nome do serviço no Docker Compose. É assim que o contentor do LibreChat chega ao SearXNG.
  • allowedAddresses é obrigatório: sem ele a pesquisa falha mesmo com o SearXNG a funcionar.
  • O DuckDuckGo costuma devolver CAPTCHAs a instâncias auto-hospedadas. Se as pesquisas vierem vazias, use engines: "google,bing,brave,startpage,qwant".

Reinicie tudo:

docker compose down && docker compose up -d

6.4 Testar a pesquisa numa conversa

  1. Abra uma nova conversa e escolha o endpoint LM Studio.
  2. Na barra de escrita, abra o menu de ferramentas e ative Web Search.
  3. Se o LibreChat abrir um ecrã de configuração da pesquisa (porque parte da configuração não está no librechat.yaml), escolha SearXNG como fornecedor e Keenable como extrator, e deixe a chave vazia (é opcional).
  4. Pergunte: “Quais são as últimas notícias sobre inteligência artificial em Portugal?”
  5. A resposta deve mostrar o passo de pesquisa e incluir fontes com ligações.

Verificação: para confirmar que os pedidos chegam ao SearXNG, corra docker compose logs -f searxng e repita a pergunta. Devem aparecer pedidos de pesquisa.

Tarefa D: faça a mesma pergunta sem a Web Search ativa e compare. Sem pesquisa, o modelo só sabe o que aprendeu no treino e pode responder de memória com números que parecem atuais. Verifique sempre se a resposta mostra o passo de pesquisa e as fontes.

Ex 7: Criar um Agente com ferramentas

Um Agente no LibreChat é um assistente com nome, instruções, modelo e ferramentas próprias. Ao contrário de um preset, o agente pode usar ferramentas de forma autónoma (pesquisar, executar código, chamar APIs).

7.1 Criar o agente

  1. No seletor de endpoints, escolha Agents.
  2. No painel lateral direito, abra o Agent Builder e clique em Create.
  3. Preencha:

    • Name: Investigador Web

    • Description: Pesquisa na web e responde com fontes (preencha sempre este campo: um agente sem Description pode falhar com erro 400 no LM Studio)

    • Instructions:

      És um assistente que responde em português, de forma concisa.
Usa a pesquisa web apenas quando a pergunta precisar de informação atual
ou factual que possa ter mudado (notícias, números, preços, cargos, datas
recentes) ou quando não souberes a resposta.
Para conceitos gerais, explicações e tarefas de escrita, responde
diretamente, sem pesquisar.
Quando pesquisares, termina com a lista das fontes (título e link).
Se não encontrares informação fiável, diz isso claramente.

    • Provider: LM Studio e o modelo carregado no Ex 0.

  4. Abra a Tool Library (biblioteca de ferramentas) e selecione Pesquisa na Web. O cartão fica com um visto verde. A engrenagem do cartão abre as definições do extrator: como o fornecedor, o reranker e o scraper já vêm do librechat.yaml, só aparece o campo da chave do Keenable, que é opcional. Pode deixá-lo vazio.
  5. Clique em Save.

A Tool Library organiza as ferramentas em:

Secção O que contém
Nativo Ferramentas que vêm com o LibreChat: Executar Código, Pesquisa na Web, Artefactos, Pesquisa de Ficheiros e Ask User (o agente pára e faz uma pergunta de esclarecimento)
Tools Plugins externos, quase todos com chave de API própria (Google, Tavily, Wolfram, Calculator, OpenWeather, geração de imagem, entre outros)
MCP servers Ferramentas ligadas por servidores MCP
Actions Ferramentas ligadas a uma API descrita em OpenAPI

7.2 Usar o agente

  1. Selecione o agente Investigador Web no seletor.
  2. Faça duas perguntas e compare:
    • “Explica o que é o Docker em 2 frases.” Deve responder sem pesquisar.
    • “Qual é a população atual de Viseu e qual a fonte?” Deve pesquisar.
  3. Observe a chamada à ferramenta de pesquisa e a resposta com fontes.

Como o agente decide pesquisar: a ferramenta selecionada na Tool Library fica disponível, mas quem decide quando a usa são as Instructions. Modelos locais pequenos nem sempre seguem bem esta regra e podem pesquisar de mais ou de menos. Para que nunca pesquise, desmarque a Pesquisa na Web na Tool Library. Para ter controlo total, use uma conversa normal e ligue a Web Search com o botão da barra de escrita.

Tarefa E: duplique o agente, mude o modelo para a OpenAI (gpt-4o-mini) e faça a mesma pergunta. Compare o modo como cada modelo usa a ferramenta. Modelos locais pequenos nem sempre chamam ferramentas de forma fiável.

7.3 Acrescentar mais ferramentas

Na Tool Library pode dar ao agente mais do que a pesquisa:

  • Pesquisa de Ficheiros: carregue um PDF para o agente e pergunte-lhe sobre o conteúdo.
  • Executar Código: permite ao agente correr código (requer chave do Code Interpreter API).
  • Actions: liga o agente a uma API externa através de uma especificação OpenAPI.
  • MCP servers: servidores de ferramentas externos configurados no librechat.yaml.

Tarefa F: crie um segundo agente, Analista de Documentos, com Pesquisa de Ficheiros ativa. Carregue um PDF e pergunte: “Resume este documento em 5 pontos.”

Resolução de problemas

Sintoma Causa provável Solução
Modelo não aparece no LibreChat Não carregado no LM Studio, ou fetch falhou Confirme http://localhost:1234/v1/models; como alternativa ponha fetch: false e o ID em default
Erro de ligação ao LM Studio O Docker não chega ao host Teste com docker exec; em Linux acrescente extra_hosts
Alterações ao librechat.yaml sem efeito Ficheiro não montado ou sem reiniciar Verifique o docker-compose.override.yml e reinicie
OpenAI não aparece Chave em falta ou sem reiniciar Confirme OPENAI_API_KEY no .env e reinicie
Erro 401 da OpenAI Chave inválida ou sem crédito Gere nova chave e verifique a faturação
Erro invalid mount path: 'searxng' mount path must be absolute Volume mal escrito no docker-compose.override.yml O volume tem de ser ./searxng:/etc/searxng; corra docker compose config para ver o resultado final
Pesquisa web falha logo Falta allowedAddresses Adicione searxng:8080 em allowedAddresses
Pesquisa web vem vazia Todos os motores falharam Troque os motores (retire o DuckDuckGo)
Erro 403 na pesquisa (nos logs do LibreChat: SearXNG API request failed ... 403) O SearXNG não está a servir JSON: formats mal colocado no settings.yml Coloque search: ao nível da raiz, com - json em formats, reinicie o SearXNG e repita o teste abaixo
Agente com LM Studio dá 400 Required (text.format nos logs do LM Studio) Agente com campos por preencher Preencha Name, Description e Instructions e grave de novo. Se persistir, mude o Provider do agente para outro e volte ao LM Studio; se continuar, use o gpt-4o-mini no agente
Agente não chama a ferramenta Modelo sem suporte a ferramentas Use gpt-4o-mini ou outro modelo com suporte a ferramentas
Agente responde com dados atuais sem pesquisar Respondeu de memória Verifique se aparece o passo de pesquisa e as fontes; reforce as Instructions

Teste de diagnóstico do SearXNG (403)

A imagem do LibreChat não tem curl, por isso corra o teste num contentor temporário na mesma rede Docker (a rede chama-se <pasta>_default, por exemplo librechat_default):

docker run --rm --network librechat_default curlimages/curl -s -o /dev/null -w "json: %{http_code}\n" "http://searxng:8080/search?q=teste&format=json"
docker run --rm --network librechat_default curlimages/curl -s -o /dev/null -w "html: %{http_code}\n" "http://searxng:8080/search?q=teste"
Resultado Significado
json: 200 e html: 200 O SearXNG está bem configurado
json: 403 e html: 200 O json não está ativo: reveja a indentação de search: no settings.yml
Ambos 403 ou erro de ligação O SearXNG não está a correr ou a rede está errada: veja docker compose logs searxng

Comandos úteis:

docker compose logs -f api        # logs do LibreChat
docker compose logs -f searxng    # logs do SearXNG
docker compose down && docker compose up -d   # reiniciar tudo

Os avisos The "UID" variable is not set são inofensivos em Windows. Pode ignorá-los.
